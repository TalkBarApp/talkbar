TalkBar сообщает о напоминаниях и событиях системными уведомлениями на этом компьютере. Кроме того, он может отправлять короткие уведомления в другие места через каналы доставки: на email, в Telegram, Slack, Microsoft Teams или на свой вебхук. И то и другое настраивается в разделе **Настройки → Уведомления**.

## Системные уведомления

**Системные уведомления** по умолчанию включены. Пока они включены, TalkBar показывает напоминания и события как системные уведомления, например:

- напоминания о запланированных сессиях (новые запланированные сессии получают напоминания, выбранные в разделе [**Настройки → Календари → Напоминания по умолчанию**](/settings/calendar-sync)) и обратный отсчёт перед автоматическим началом сессии;
- предупреждение перед тем, как сессия без вашего участия завершится сама (**Уведомлять перед автозавершением** в [настройках голоса](/settings/voice)).

Когда окно TalkBar на переднем плане, TalkBar показывает эти уведомления внутри приложения, чтобы одно и то же уведомление не приходило дважды.

В разделе **Настройки → Уведомления → Системные уведомления**:

| Элемент | Что делает |
| --- | --- |
| Переключатель **Системные уведомления** | Включает или выключает системные уведомления от TalkBar. |
| **Системные настройки** | Открывает системные настройки уведомлений, где также можно разрешить или заблокировать TalkBar. |
| **Отправить тест** | Показывает тестовое уведомление, чтобы проверить, что система его отображает. |

::callout{icon="i-heroicons-light-bulb" color="primary"}
Если тестовое уведомление не появилось, проверьте, что уведомления TalkBar разрешены в настройках системы и что режим «Не беспокоить» выключен.
::

Напоминания о запланированных сессиях задаются для каждой сессии или серии. Подробнее — в разделе [Планирование и подготовка](/sessions/scheduling-and-preparing).

## Каналы доставки

Канал доставки — это место за пределами TalkBar, куда можно отправлять сообщения. Каналы используются для трёх целей:

- автоматические уведомления о ваших сессиях (см. [ниже](#автоматические-уведомления));
- **Отправить материал** и **Отправить ссылку**, когда вы [делитесь](/sharing/share-links);
- [автоматическая отправка](/sharing/share-links#автоматическая-отправка) итогов.

| Тип канала | Что понадобится |
| --- | --- |
| **Email (SMTP)** (**Email** в форме **Создать канал**) | Почтовый аккаунт для отправки. Для готовых настроек **Gmail**, **Outlook** и **Yahoo** нужен пароль приложения от этого провайдера. **Свой SMTP** работает с любым другим сервером (хост, порт, безопасность, имя пользователя, пароль). |
| **Telegram** | Бот, созданный через @BotFather, и чаты или каналы, в которые он должен писать. Добавьте бота в группу или канал, отправьте туда любое сообщение и нажмите **Определить ID чатов** или вставьте ID чатов сами. |
| **Slack** | URL входящего вебхука из приложения Slack. |
| **Microsoft Teams** | URL вебхука из Teams Workflows с триггером *When a Teams webhook request is received* и проверкой подлинности *Anyone*. Старые URL соединителей Office 365 не поддерживаются. |
| **Свой вебхук** | HTTPS-адрес, принимающий JSON, и при необходимости имя и значение заголовка авторизации. |

Можно создать несколько каналов любого типа и включать или выключать каждый из них.

### Добавление канала

1. Откройте **Настройки → Уведомления** и нажмите **Добавить канал** (или **Создать канал** в разделе **Каналы доставки**).
2. Выберите тип канала и следуйте шагам. Для Slack, Teams и своих вебхуков всё помещается на одной странице, а короткая ссылка на справку ведёт к пошаговым инструкциям.
3. При желании выберите [автоматические уведомления](#автоматические-уведомления), которые будет получать этот канал.
4. Нажмите **Отправить тест**, чтобы проверить доставку, затем нажмите **Создать канал**.

### Автоматические уведомления

Каждый канал может получать эти короткие уведомления. При создании канала ни одно не выбрано.

| Уведомление | Когда отправляется |
| --- | --- |
| **Сессия завершена** | Сессия закончилась. |
| **Итоги готовы** | Итоги сессии подведены впервые. Текста итогов в уведомлении нет. |
| **Системные оповещения** | Что-то требует вашего внимания, например проблема с ИИ или автоматическая запись, которая не смогла начаться. |
| **События приложения** | Другие события TalkBar, например завершённая отправка материалов. |

Чтобы отправлять итоги целиком вместо короткого уведомления, используйте [автоматическую отправку](/sharing/share-links#автоматическая-отправка).

### Управление каналами

Каналы перечислены в разделе **Настройки → Уведомления → Каналы доставки**. У каждого канала есть:

- **Изменить**: поменять название, параметры по умолчанию и уведомления. Чтобы ввести новый пароль, токен бота или URL вебхука, нажмите **Заменить данные доступа**; сохранённые данные доступа больше никогда не показываются.
- **Отправить тест**: отправить тестовое сообщение. Оставьте адресата пустым, чтобы использовать параметры канала по умолчанию.
- Переключатель: включить или выключить канал, не удаляя его.
- **Удалить**: удалить канал безвозвратно.

Если сообщение не удалось доставить, у канала показана последняя **Ошибка доставки**.

## Получатели email и чаты Telegram по умолчанию

У каналов Email можно задать **Получатели по умолчанию (необязательно)**, а у каналов Telegram — **ID чатов доставки по умолчанию (необязательно)**. Автоматические уведомления уходят этим адресатам по умолчанию. Когда вы делитесь материалами или настраиваете правило автоматической отправки, получателей для каждого канала вы выбираете там.

## Формат своего вебхука

Для технических специалистов: свой вебхук получает один JSON-запрос `POST` на каждое сообщение.

```json
{
  "schemaVersion": 1,
  "id": "stable-delivery-id",
  "type": "share.delivered",
  "occurredAt": 1793336166000,
  "title": "Planning",
  "body": "Decisions and action items selected by the sender",
  "data": { "...": "depends on the event" }
}
```

- Заголовок `Idempotency-Key` повторяет `id`. По нему можно отбрасывать дубликаты.
- TalkBar повторяет отправку при ошибках соединения, превышении времени ожидания, ответах HTTP 408, 429 и 5xx. Если время ожидания истекло, сообщение всё равно могло быть доставлено, поэтому дубликаты возможны.
- Другие ответы 4xx и перенаправления завершаются ошибкой без повтора.
- Ваш получатель должен допускать дополнительные поля: новые поля могут появиться.
- Каждое уведомление — один JSON-запрос; если данные превышают лимит размера, отправка завершается ошибкой, а не разбивается на части.

Slack получает обычные сообщения, а Teams — карточки Adaptive Cards. Вебхуки отправляют только текст; вложения не передаются.

## Где хранятся данные доступа каналов

Пароли, токены ботов и URL вебхуков хранятся на этом компьютере в зашифрованном виде. После сохранения они больше не показываются. Если вы переносите TalkBar на другой компьютер, их может понадобиться ввести снова; см. [Резервное копирование и восстановление](/data/backup-and-restore#пароли-api-ключи-и-токены).

На рабочем компьютере администратор может отключить некоторые типы каналов или внешние уведомления. Тогда TalkBar показывает уведомление о том, что именно заблокировала ваша организация.
